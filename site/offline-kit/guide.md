# 智策 / zcagent · Windows 离线交付说明

给实施人员的一页说明。拷到目标机器的U盘/内网共享里，配合本目录的两个安装包使用。

## 包里有什么

| 文件 | 用途 |
|---|---|
| `zcagent-desktop-windows-amd64-<版本>.exe` | 安装版：开始菜单图标 + 桌面窗口 |
| `zcagent-portable-windows-amd64-<版本>.zip` | 便携版：解压即用，自带 Python 与 Node 运行时 |
| `SHA256SUMS.txt` | 两个包的校验值（由打包命令从 GitHub Release 的 digest 生成） |
| `guide.md` | 本页 |

## 第一步：先校验，再运行

在目标机器上（PowerShell，切到本目录）：

```powershell
Get-FileHash .\zcagent-desktop-windows-amd64-<版本>.exe -Algorithm SHA256
```

把结果与 `SHA256SUMS.txt` 对照，**不一致就不要装**（多半是传输被截断——本项目实测遇到过
`gh release download` 报告成功但只落了 37% 字节的情况）。

## 系统要求

- Windows 10 1903 及以上，x64（实测环境 Windows 10 10.0.19045）
- 磁盘（z11 实测）：安装版程序目录约 235 MB，便携版解压后 758 MB（≈723 MiB，与下载页标的
  724 MiB 一致）；首次运行还会把绿色包解到 `~\.octop\portable`，**干净状态 758 MB**，
  运行数据另算
- **`~\.octop\portable` 会长大，给客户算磁盘时要留余量**：知识库真的跑过一次之后，
  onnxruntime / numpy / Pillow / tokenizers / huggingface_hub 这些依赖会装进
  `portable\runtime\Lib\site-packages`，实测多占 151 MB（本机 758 MB → 946 MB）。
  这不是残留也不是重复解压——`runtime\Lib` 从 32 MB 变 172 MB，`packages\` 只多 47 MB，
  差额全在真正被 import 过的那些包里。内网批量部署请按 **≈1 GB** 预留这一项
- 安装版需要 **Microsoft Edge WebView2 运行时**（较新的 Win10/Win11 已内置，缺失时安装器会提示）
- 便携版**不需要**安装 Python 或 Node。z10 起包里就带着 Node 22.20.0 —— 之前从 npm 装的
  连接器命令行工具（agently 邮件 / 飞书 / 企微）会报「未找到 npm，请先在 zcagent 主机安装 Node.js」，
  现在不需要用户自己装任何东西。这份 Node 只被前置进本程序自己的 PATH，**不写系统 PATH、
  不在目标机上安装任何东西**
- 网络：只需要能访问你配置的模型 API；软件本身不外联。一个例外——在界面里点「安装命令行工具」时，
  它会执行一次 `npm install -g`，那一步要能到 npm 源（内网机器请配内网 npm 镜像，
  或提前把包放进目标机）

## 安装版

1. 双击 `.exe`。若 SmartScreen 拦一道蓝窗：点「更多信息」→「仍要运行」（安装包未做代码签名，
   上游同样未签名发布；内网复制过去的文件通常不带网络标记，不弹）。
2. 按向导装到当前用户目录，**不需要管理员权限**。
3. 从开始菜单启动「智策」。它会在本机起服务（默认 `127.0.0.1:8088`）并打开窗口。
4. 首次启动进入初始化向导：验证口令 → 数据库（默认本机 SQLite）→ 建管理员 → 配模型（可跳过）。
   一次性口令在服务器控制台黄框里，也写在 `%USERPROFILE%\octop-login.txt`。

静默安装（批量部署）：

```powershell
.\zcagent-desktop-windows-amd64-<版本>.exe /S /D=C:\zcagent
```

## 便携版

1. 解压到任意目录（路径含空格也可以）。
2. 双击 `start.bat`。换端口或数据目录：`start.bat --port 8090 --home D:\zcagent-data`。
3. 浏览器打开 `http://127.0.0.1:8088`，走同一套初始化向导。

## 数据、迁移与卸载

- 数据默认在 `%USERPROFILE%\.octop`（便携版为解压目录下的 `.\data`）：账号、专家、对话与记忆、
  技能、通道与模型配置都在里面。
- 迁移 = 拷走整个数据目录。
- 卸载：安装版从「应用和功能」卸载，便携版直接删目录；两者都不动数据，重装即可继续用。
- **一条要知道的残留**：桌面客户端首次运行会把绿色包解到 `~\.octop\portable\`（z11 实测
  758 MB 起，用过知识库后约 946 MB），
  卸载**不会**删除它（它位于数据目录内，卸载器按设计不动数据）。要彻底清理，卸载后手动删除
  `~\.octop\portable`。

## 更新

- 应用内：「应用设置 → 应用更新 → 检查更新」。**默认不检查公共源**，所以刚装好时这里不会提示新版本，
  这是刻意的——避免把别人的构建装进内网机器。
- 内网自建索引（devpi 等）时设这两个变量后才会启用，并且安装候选只来自该索引：

```powershell
set OCTOP_UPDATE_JSON_URL=http://<内网索引>/<user>/<index>/{name}/
set OCTOP_UPDATE_SIMPLE_URL=http://<内网索引>/<user>/<index>/+simple/
```

- 也可以直接换包：下载新版本，覆盖安装即可，数据保留。

## 内网：向量模型预下载

智策在**空闲时会后台下载一次默认向量模型**（`BAAI/bge-small-zh-v1.5`，约 92 MB），
这样用户第一次打开「知识库设置」不用干等下载。它走 COS / huggingface / hf-mirror 三个源，
**三个都连不通就静默放弃**：不弹错、不占界面，最多再试两次就不再尝试。
所以内网机器什么都不配也不会出问题，代价只是开机 90 秒后约 4 秒的后台探测。

如果连这次探测都不想要（例如严格管控出站流量的环境），在启动前设一个环境变量彻底关掉：

```powershell
# 当前会话
set OCTOP_KNOWLEDGE_MODEL_PREFETCH=0
# 或永久写入系统环境（管理员）
setx OCTOP_KNOWLEDGE_MODEL_PREFETCH 0
```

关掉之后，用户打开「知识库设置」时也不会自动开始下载，需要他自己点「下载」按钮。

## 公网访问（z12 起，默认关闭）

**设置 → 网络** 有一个「公网访问」开关，走 Cloudflare 隧道，让外面用一个公网网址访问这台机器。
交付时**默认是关的**，不要替客户打开，也不要把它当成"配置好交付"的一部分。

如果客户主动要求，实施时要知道：

- **组件不在包里。** cloudflared（约 53 MB）是第一次点开启时从 github.com 下载的。
  **纯内网、不能出网的机器一定下不来**——在能出网的机器上下好
  `cloudflared-windows-amd64.exe`（版本钉 `2026.10.1`），放到
  `%USERPROFILE%\.octop\tunnel\bin\` 再开。产品会按 SHA-256 校验，
  校验不过直接报错，不会静默用一份来路不明的二进制。
- **开启有四道硬门**：已完成首启且有管理员账号、**登录验证码开着**、接口文档没对外开放、
  平台受支持。任何一项不满足开关是灰的，界面上每一项都带「去设置」。**不要为了让它亮起来
  去关验证码**——那等于把撞库门槛拆了。
- **开启时必须重输一次当前登录口令**。库里只有哈希，不拿到明文既判断不了口令强度、
  也证明不了点按钮的人知道口令。口令不落盘、不进日志。
- **「公网安全模式」默认开，别关。** 它屏蔽的是从公网进来的请求使用：终端、浏览器、
  远程桌面/手机、本机文件浏览、接口文档、TLS/更新/备份管理。本机与内网不受影响。
  专家能直接操作这台电脑，关掉它之后风险等级是"这台机器沦陷"。
- **地址是一次性的**：每次重新开启都换随机网址，服务重启也不自动恢复（故意的——自动重连
  只会让之前发给客户的链接悄悄失效）。所以**不要把 trycloudflare 地址写进交付文档或客户手册**。
  客户要长期固定域名，得配 Cloudflare 的正式隧道，**本版本没有做**。
- **国内可达性不稳定。** 产品开启后会真的从公网地址回访一次自己，通过才显示"已连通"。
  刚建好时显示"已建立·未验证"是常见的（边缘生效要几秒到几十秒），界面上有「重新验证」。
  验收时**必须站在客户的外部网络环境看这个网址能不能打开**，不能只看进程活着或界面显示已开启。
- 开关的开、关、改安全模式都会写审计日志（`管理 → 安全防护 → 审计`，事件 `tunnel.*`）。

更完整的产品侧说明见仓库 `docs/public-access.md`。

## 已知限制

- **`工作台 / 终端` 在 Windows 上不可用**（上游按设计依赖 `pty`，仅 Linux/macOS 提供）。
- 只出 Windows x64 包；macOS / Linux / ARM64 未交付。
- 模型能力取决于接入的模型档位；技能是否被严格遵循与模型档位相关，交付时按实际模型评估。
- 专家可在工作区 `.octop\.env` 写明文凭据（用于接自己的 MCP/外部服务）。这是产品权衡后的选择，
  因此**不要向客户承诺"密钥不落盘"**；对合规要求高的客户单独评估。
- **`GET /api/providers` 会把各模型提供商的 API Key 明文返回给任何已登录用户**（界面自己打码，
  所以看不出来）。这是上游既有设计。**开了公网访问且机器上有多人登录时，不要给普通员工账号**——
  在那种部署下他们能读到全部密钥。
