{{NAME_ZH}} 使用指南

面向第一次接触 {{NAME_ZH}} 的使用者与交付同事。每章都是同一套顺序：做什么 → 在界面哪里点 → 会看到什么 → 卡住了怎么办。

适用版本 {{VERSION}}（发布于 {{RELEASE_DATE}}）· 实测环境 {{TESTED_ON}} · 内置运行时 {{RUNTIME}}

智策是什么

{{NAME_ZH}} 是一套自托管的多用户 AI 助手平台：服务跑在你自己的机器或自己的 服务器上，对话、文件、记忆与凭据都存在本机数据目录里，不经过第三方。

每位使用者有自己的账号、自己的专家与自己的数据可见范围；管理员在同一个实例里统一配模型、管用户。

  • 桌面客户端（Windows）：双击安装包，带托盘与原生窗口，日常使用走这条。
  • 绿色便携包：解压后 start.bat 即可，自带 Python 运行时，不要求目标机器装 Python 或 Node。
  • 内网离线交付包：安装程序 + 便携包 + 校验和 + 运维说明，一个 U 盘带走。

所有数据默认在 %USERPROFILE%\.octop（可用环境变量 OCTOP_HOME 改到别处）。 这一条决定了备份、迁移和卸载的行为，账号、密码与备份一章有专门说明。

十分钟装好

推荐路径：下载桌面客户端，一路下一步。

  1. 到 下载页 取 {{EXE_NAME}}（{{EXE_MIB}} MiB，SHA256 摘要 {{EXE_SHA_SHORT}}）。
  2. 双击运行安装程序。首次运行 Windows 可能弹 SmartScreen 提示，选择「更多信息 → 仍要运行」。
  3. 装完后从开始菜单启动 智策。第一次启动会把内置运行时解压到 ~\.octop\portable（约 {{PORTABLE_MIB}} MB），期间窗口会显示解压进度， 这一步只做一次。
  4. 浏览器未被自动拉起时，手动打开 http://127.0.0.1:8088。
校验下载物是交付流程的一部分，不是可选动作。PowerShell 里 Get-FileHash .\{{EXE_NAME}} 的输出应当与下载页标注的 SHA256 一致。

需要在没装过 {{NAME_ZH}} 的机器上批量部署，或者要给离线环境用，取 {{ZIP_NAME}}（{{ZIP_MIB}} MiB）解压即用；内网与离线部署一章讲端口、 更新源与向量模型怎么配。

第一次打开：设置向导

全新机器第一次启动会进入设置向导，它要完成两件事：

  1. 建立管理员账号——用户名与密码由你自己设定。这台机器之后就用这套口令登录，系统不预置任何通用密码。
  2. 配置至少一个模型供应商——没有模型，助手无法回答问题。

向导的一次性口令会打印在服务控制台，并写入 %USERPROFILE%\octop-login.txt，用完即失效。这个文件是本机临时凭据， 不要外发、不要提交到任何仓库。

跳过模型这一步能进界面，但对话起不来——向导里的模型步骤是必做项，不是可选项。 之后想补，随时可以在 管理 → 模型 里加。

装完之后要改密码、忘记口令，见 账号、密码与备份。

界面地图

分组包含什么时候用

客户端窗口左上是品牌标识，版本号显示在它的下方，形如 v{{VERSION}}——交付时让对方核对这一处就够了，不必去翻菜单。 窗口里点右键只有两项：上一页 与 重新加载系统；浏览器自带的「另存为 / 打印」在客户端里不出现。

配置第一个模型

入口：管理 → 模型。模型是助手唯一的能力来源，配好它才有后面的所有事。

  1. 选择预设供应商（填 API Key 与模型名即可），或用 自定义供应商接入任何 OpenAI 兼容端点——企业自建网关、内网推理服务都属后者。
  2. 保存后点测试连接。这一步真的发一次请求，能立刻暴露地址、Key 或模型名写错。
  3. 把要用的模型设为默认，之后新建的专家会继承它。
API Key 只写进本机数据目录里的配置，不下发到浏览器，也不会出现在导出内容中。 但请注意：专家工作区可以自己写 .env 存放凭据，那是明文文件—— 对凭据有合规要求的客户请单独评估，不要承诺「密钥不落盘」。

模型能力直接决定助手表现：技能（Skill）是否被严格遵循、长上下文里能否守住指令，与模型档位相关。 交付时请按现场模型实测，不要拿演示环境的结论当承诺。

建第一个专家

专家（Expert）是一位有自己人设、自己资料、自己权限的助手。入口： 专家 页 → 从模板创建，或新建空白专家。

  1. 先在 专家市场 里挑一个贴近岗位需求的模板（客服、分析师、文档助手等），再按你们的实际叫法改提示词。
  2. 定人设与语言风格——人格（Persona）决定它怎么说话，系统提示决定它守什么规矩。
  3. 指定它能用哪些技能与知识库，决定它能查到什么。
  4. 设可见范围：只给自己用，还是共享给同事。

每位专家有自己的工作区，里面会预置人设与工作约定文件（例如 SOUL、USER、 MEMORY），也允许专家自己写文件。要改「它记住的东西」，在工作区里改这些文件比在对话里反复强调有效。

对话与记忆

对话 页选一位专家开始。会话历史、附件与记忆都存在本机数据目录， 换一台机器只要把数据目录带走就都在。

  • 引用：挂知识库的会话会带上来源，回答里能看到引自哪份文档。
  • 跨专家协作：一个任务可以交给另一位专家继续，适合「查资料的」和「写结论的」分开。
  • 记忆：长期偏好写进专家工作区文件，比在对话里重复说更可靠。

用量在 Token 统计 里按用户与模型查看，内网按人分摊成本时用得上。

知识库：让助手按你们的制度回答

知识库把你们的文档建成索引，对话时按需检索并给出出处。典型用法是把请假、报销、流程规范一类 制度文件放进去，让助手据此判断。

  1. 打开 设置 → 知识库，先启用实例级开关。
  2. 选一个向量模型并等待它下载完成（下面有选型建议）。
  3. 新建知识库。名称与描述已经带着示例值（例如「智策科技公司制度知识库」）， 改成你们的实际名称即可，不必从空白开始想。
  4. 上传文档，等索引完成，然后在对话里引用这个知识库提问。

向量模型怎么选

默认列表只推荐中文可用的模型，每一个都标了体积和一句话优缺点；点「高级选项」才会展开其余。

模型体积适合代价
BAAI/bge-small-zh-v1.5（默认） 约 92 MB 中文制度问答的第一选择，桌面机器无需 GPU 也能跑 只擅长中文，跨语言资料建议换更大的模型
jinaai/jina-embeddings-v2-base-zh 约 640 MB 中英混排的公司资料，检索质量更稳 体积与首次索引时间都明显上升
paraphrase-multilingual-mpnet-base-v2 约 1.0 GB 多语言混合团队，无需调用方做任何预处理 本地算力要求最高
请谨慎选择展开列表里 intfloat/multilingual-e5-* 一类模型：这类模型要求查询与文档 两侧分别加不同前缀，检索质量对用法敏感。{{NAME_ZH}} 已按模型集中处理这件事，但仍建议先小范围验证再推广。 图文类模型不会被列进知识库选项——那是错误用法。

第一次不用干等下载

客户端会在启动约 90 秒后在后台下载一次默认向量模型（约 92 MB）， 这样你第一次打开知识库设置时不必盯着进度条。它最多尝试三次，失败就保持安静、不打扰你， 等你真的打开设置时再显式下载。

三个下载源（腾讯云 COS / huggingface.co / hf-mirror）都连不通时，它会静默放弃： 不弹错、不重试刷屏。内网机器什么都不用配，代价只是启动后约四秒的探测。想彻底关掉， 启动前设 OCTOP_KNOWLEDGE_MODEL_PREFETCH=0（见 配置与环境变量）。

技能与插件

技能（Skill）是给专家的一段可复用工作说明书，插件是更重的能力扩展。 设置 → 技能包 负责安装与启用，专家页决定它能用哪些。

  • 先在小范围验证：同一句话在不同模型档位上的遵循程度不同。
  • 技能文件本身是文本，可评审、可版本化——把重要流程写进技能而不是口头约定。
  • 第三方插件按实例安装，启用范围由管理员在 管理 → 插件 控制。

通道：让助手出现在你已经在用的地方

通道（Channel）把一个实例接到消息平台：同事在群里 @ 一下就能用，不需要再打开网页。 入口在 设置 → 通道，按平台分别配置凭据与回调地址。

  • 每个通道可以绑定不同的专家，「报销问题找 A，技术问题找 B」是常规做法。
  • 回调地址必须能被平台访问到。本机演示可用内网穿透，正式交付建议直接暴露在带 TLS 的域名上。
  • 换行即发送等平台行为差异，配置页有开关，遇到「消息被拆成几条」先查这里。

连接器与 MCP

连接器负责把外部系统接进来：既有内置应用的直连，也支持标准 MCP（Model Context Protocol） 服务。入口在 设置 → 连接器。

  1. 先确认权限边界：给只读账号，不要一上来就给写权限。
  2. 需要 OAuth 的连接器会走授权流程，令牌存在本机数据目录。
  3. MCP 服务可以来自公司内部，任何能按协议提供服务端点的程序都能接。

自动化与远程执行

定时任务

自动化 → 定时任务 让专家按计划自己跑一次：每天整理昨日工单、 每周一出上周摘要。任务带的是提示词与专家，所以行为与手工对话完全一致，只是触发方式不同。

ACP、远程桌面

ACP 把编码代理接到本地终端，远程桌面 让助手在受控桌面环境里操作。两者都属于「让助手动手」的能力，交付前要按客户的安全策略单独评估。

工作台里的终端在 Windows 上不可用，这是上游按设计只提供 POSIX（Linux/macOS） 的 pty 支持，不是安装出错。需要命令行工作请走 ACP 或本机终端。

账号、密码与备份

忘记口令

登录页有 忘记密码？。在本机打开时（地址是 127.0.0.1 或 localhost），它可以在界面里直接重设管理员口令， 不需要打开终端；从别的机器访问时这个入口不会出现。

命令行也能做到同样的事，作为兜底：先停服务，再执行 octop user passwd <用户名>。

数据在哪、怎么迁

内容位置
账号、模型与供应商配置、通道、专家、会话与记忆~/.octop 内的数据库与目录
知识库原文与索引同一数据目录下
内置运行时（客户端首次启动解压）~/.octop\portable，约 {{PORTABLE_MIB}} MB

迁移 = 停服务后整目录拷走，换机、换盘、备份都是这一个动作。备份前先停服务， 避免拷到写入中途的数据库文件。

卸载不会删除数据目录，重装即可接着用。唯一要知道的残留：客户端解压出来的 ~/.octop\portable 位于数据目录内，卸载器按设计不动数据，要彻底清理请手动删除该子目录。

内网与离线部署

目标是把助手放进一个不通公网的环境，并且之后能自己升级。

  1. 取离线交付包：安装程序、便携包、SHA256SUMS.txt 与运维说明。 落地第一步永远是核对校验和。
  2. 没有外网时，向量模型的后台下载会自然失败并保持安静；需要离线可用， 提前把模型放进数据目录或在有网的一侧下载后随目录迁移。
  3. 软件包更新走内网索引（devpi 等）。注意 devpi 与 PyPI 的「查版本」接口 URL 形状和 JSON 结构都不同，需要显式给两个模板： 
    set OCTOP_UPDATE_JSON_URL=http://<内网索引>/<user>/<index>/{name}/
set OCTOP_UPDATE_SIMPLE_URL=http://<内网索引>/<user>/<index>/+simple/
    配了自有索引后，安装候选只来自该索引，不会再回落公共源—— 否则「立即更新」可能把别人的包拷进内网机器。
  4. 默认不检查公共源，所以刚装好时「应用更新」不会提示新版本，这是刻意的。

也可以直接换包：下载新版本覆盖安装，数据保留。桌面客户端的更新逻辑另有一条要知道的规则—— 判断「要不要替换已解压运行时」的比较器在 exe 里，不在解压出来的运行时里。 装过旧客户端的机器请重新运行一次新安装程序，界面语言、图标与启动动画才会对。

配置与环境变量

界面里能改的都在这里；只有几个部署级开关走环境变量。

变量作用什么时候要设
OCTOP_HOME数据目录根，默认 ~/.octop装到移动盘、多实例并存
OCTOP_BIND_HOST / OCTOP_PORT监听地址与端口，默认 127.0.0.1:8088局域网共享访问、端口被占
OCTOP_KNOWLEDGE_MODEL_PREFETCH后台下载默认向量模型的总开关严格管控出站流量时设 0
OCTOP_UPDATE_JSON_URL / OCTOP_UPDATE_SIMPLE_URL内网索引的查版本与安装地址离线环境需要自更新
OCTOP_REQUIRE_SETUP_PASSWORD首启向导一次性口令的要求批量预置时按策略调整
OCTOP_DATABASE_*切 PostgreSQL 驱动、库名、地址多人高并发实例

端口一被占用，先确认是不是自己已有一个实例在跑，再谈改配置。

命令行速查

界面能做的事大部分都有对应命令，运维脚本化时用。装好之后直接运行 octop <命令>， 客户端环境里用 ~\.octop\portable\launch.py 那一套。

命令做什么
octop run启动服务（客户端也是拉这个）
octop user账号管理与口令重设（忘记密码的兜底路径）
octop provider / octop models模型供应商与模型清单
octop agent专家的增删查改
octop cron定时任务
octop channel通道
octop skills / octop plugin技能与插件
octop backup备份与恢复
octop config读实例配置
octop admin管理操作
octop acp编码代理接入
octop service注册为系统服务
octop update检查与安装更新
octop chats / octop memory会话与记忆数据
octop captcha登录验证码相关
octop clean / octop init / octop version / octop completion清理、初始化、版本、Shell 补全

任何命令加 --help 看参数；命令名以实际二进制为准。

常见问题

装好了但界面是英文

早于 {{VERSION}} 的若干安装包有这个问题（内置外壳的语言默认与运行时替换逻辑相关）， 修复已进产品。已装旧包的机器不会被自己的更新检查修好， 请重新下载并运行一次当前版本的安装程序。

知识库显示「已下载」，但用不起来

这是 {{VERSION}} 之前版本的一个真实缺陷：从镜像源下载的模型在缓存里的目录写法， 加载器认不出，于是加载仍要联网。新版本已修正写法，并会在加载前 自动把旧缓存改成正确结构，所以老机器不用重新下载就能恢复。 如果仍在旧版本上，先用界面里的「测试」按钮确认，再决定升级。

为什么默认模型只有三个

默认列表只放中文可用、体积合理的模型，每个都写了一句话优缺点；其余收在「高级选项」里。 之前有过一次把整个目录（包括图文模型）倒进设置页的情况，会让人选中一个对知识库完全错误的模型。

忘记管理员口令

在本机打开登录页，用 忘记密码？ 直接重设；或停服务后执行 octop user passwd <用户名>。

端口 8088 打不开

先确认服务在跑（托盘图标 / octop run 的日志），再看是不是有另一个实例占了端口。

客户端里怎么开 F12

客户端是交付产品，不提供开发者入口；需要排查请用浏览器访问 http://127.0.0.1:8088。

已知限制

  • 桌面客户端与便携包目前只出 Windows x64；macOS / Linux / ARM64 未交付。
  • 工作台 → 终端 依赖 POSIX pty，Windows 上按设计不提供。
  • 专家可以在工作区里写明文凭据（用于接自己的外部服务）。这是产品权衡后的选择， 因此不要向客户承诺「密钥不落盘」；合规要求高的客户单独评估。
  • 技能是否被严格遵循、长上下文里的稳定性都与模型档位相关，需按现场模型实测。
  • 桌面客户端解压的运行时目录不会被卸载删除（约 {{PORTABLE_MIB}} MB），需要手动清理。

发现问题或需要别的形态，请在你们的交付渠道里反馈。附两样东西就够：客户端左下角 logo 下方显示的版本号，以及出问题时的操作步骤。
