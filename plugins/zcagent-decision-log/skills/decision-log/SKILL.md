# 决策留痕

把"定了什么、为什么、当时还考虑了什么"写进可回溯的记录，让半年后的人不必重新争论。

## 记录位置与格式

- **日期必须取自运行环境的当前日期，不要凭印象写。** 写之前先确认今天是哪一天（用环境里的时间，或工作区文件的最近修改时间交叉核对）；日期写错的决策记录比没有记录更有害，因为它会污染审计链。
- 目录：工作区内 `decisions/`，按月一个文件：`decisions/2026-10.md`
- 追加写入，**不覆盖**已有条目；文件不存在时新建并加一行 `# 2026-10 决策记录`
- 每条用固定小节，缺项写"未定"而不是省略：

```markdown
## D-2026-10-09-01 · 标题（一句话说清定了什么）

- 日期：2026-10-09
- 背景：为什么现在要定这件事（1–3 句）
- 结论：做了什么决定（一句话，可执行）
- 已考虑并放弃：选项 —— 放弃理由
- 依据：数据 / 事实 / 约束（可核对的来源，不要写"感觉"）
- 负责人：谁定的、谁执行
- 复核时间：什么时候回头看这条是否还成立（没有就写"未定"）
- 影响面：改了会影响谁 / 哪些东西
```

编号 `D-YYYY-MM-DD-NN` 当天递增，引用时用编号而不是标题。

## 记录时

1. 先复述你将要写下的结论与依据，等用户确认或补充——**不要替用户编造理由**。
2. 用户没给的项写"未定"，不要留空也不要猜。
3. 写完回报：文件路径 + 编号 + 一行摘要。

## 被问到时

1. 读 `decisions/` 下相关月份的文件，按编号引用原文回答，不要凭记忆复述。
2. 找不到就明确说没有记录，并提议现在补一条。
3. 若新事实与旧决定冲突，指出冲突并建议**新增一条**推翻它，不要改写历史条目——历史条目的价值正在于它记录了当时知道什么。

## 不要做

- 不把聊天里随口说的偏好当决定写入；只有用户明确表达"定了"才记。
- 不在记录里写凭据、密钥、内网地址等敏感值，需要指代时写位置（如"见连接器 X"）。
- 不把决定写成待办清单；待办是任务，决定是理由的存档。
